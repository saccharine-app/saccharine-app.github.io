Introduction: Native BPMN 2.0 for Laravel

saccharine/bpmn turns standardized visual process diagrams into executable, queue-driven workflows inside your Laravel application.

What is BPMN 2.0?

Business Process Model and Notation (BPMN 2.0) is an open, vendor-neutral standard maintained by the Object Management Group (OMG). It establishes a standardized visual syntax—flowcharts composed of events, activities, gateways, and sequence flows—designed to bridge the communication gap between business analysts and software developers.

In traditional applications, workflows drawn on whiteboards inevitably diverge from code. Business rules end up scattered across nested controller conditions, queued jobs, cron schedules, and event listeners.

With this package, the visual diagram is the executable source of truth. The XML graph drawn in your browser is compiled directly into database records and executed by your existing Laravel queue workers.

The Integration Bridge

saccharine/bpmn is not an engine built from scratch in isolation. It serves as an integration bridge uniting battle-tested open-source technologies:

  • Visual Canvas via bpmn-js (Camunda): Embeds a zero-dependency SVG modeler and execution viewer in your web browser or Filament admin panel.
  • Durable Coroutines via durable-workflow: Provides deterministic coroutine persistence. Workflows pause, hibernate to the database, and resume without holding queue worker threads or memory.
  • Sandboxed Decisions via Symfony ExpressionLanguage: Evaluates conditional branching on Exclusive Gateways safely against execution payloads without raw PHP eval().
  • Native Laravel Infrastructure: Runs on your existing database connections and queue workers without requiring dedicated Java servers or external daemons.

Architectural Principles

1. Blueprint vs. Runtime Separation

The engine maintains a strict architectural boundary between workflow blueprints and runtime state:

  • Blueprints (Compiled Definitions): When a BPMN diagram is saved, the engine's XPath compiler parses the XML and writes the graph structure into relational tables (workflow_definitions, workflow_versions, workflow_nodes, and workflow_edges). At runtime, token routing executes indexed SQL queries rather than re-parsing raw XML strings.
  • Runtime State (Tokens & Audit Logs): Running workflow instances track active execution pointers inside workflow_tokens, while workflow_histories records an immutable audit log of completed steps and data snapshots.

2. Zero Worker Blocking

Long-running processes (such as awaiting a manager's approval or waiting 48 hours for a customer response) never block a queue worker.

When a workflow reaches a User Task or Timer, the coroutine yields execution, records its state snapshot into the relational database, and releases the queue worker immediately. When the required event or approval signal occurs, the workflow is pushed back onto the queue to continue from that exact step.
