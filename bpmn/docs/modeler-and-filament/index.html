Modeler & Filament Integration

saccharine/bpmn provides visual tooling for both authoring workflows and monitoring active tokens in real time. It operates as a standalone web interface or embeds seamlessly into Filament v5 panels.

1. The Visual Modeler (bpmn-js)

The package embeds Camunda's open-source bpmn-js web modeler directly inside a responsive Blade view.

Capability-Driven UI Filtering

The standard BPMN 2.0 specification contains over 80 node types and markers, many of which (such as manual message choreographies or complex transaction boundaries) are unnecessary for typical queue automation.

To prevent users from drafting diagrams containing nodes that the backend queue engine cannot execute, the designer uses a capability registry paired with non-destructive bpmn-js filter middleware. Rather than replacing core providers or hand-crafting drag-and-drop primitives, the UI derives visibility across all interactive surfaces from a single source of truth:

  • engineCapabilities.js: The central registry defining engine-supported BPMN element types (DEFAULT_SUPPORTED_ELEMENTS) and their corresponding action identifiers across the palette, context pad, and replace menu. Hosts can dynamically override this capability set at runtime via the fourth argument of window.initBpmnDesigner(initialXml, templates, saveCallback, supportedElementsOverride).
    • Start Events & End Events
    • Service Tasks (Automated activities)
    • User Tasks (Human approval and form nodes)
    • Call Activities & Sub-Processes
    • Exclusive Gateways (XOR conditional splits)
    • Parallel Gateways (AND concurrent splits and joins)
  • FilteredPaletteProvider.js: Intercepts palette creation actions generated by bpmn-js and prunes entries not present in the capability registry. Canvas interaction tools (hand, lasso, space, and global connect tools) remain fully functional, and no internal provider arrays are manually modified.
  • FilteredContextPadProvider.js: Filters the context pad actions when clicking an existing canvas element. Unimplemented append actions are removed, while core editing tools (such as sequence flow connections, shape deletion, and the type transformation wrench) are preserved. Direct append shortcuts for engine-supported types (like Service Tasks and User Tasks) are injected where missing.
  • FilteredReplaceMenuProvider.js: Intercepts the "wrench" type replacement menu (bpmn-replace) and strips out transformation targets not supported by the queue engine. As new backend handlers are implemented, adding their BPMN type to engineCapabilities.js automatically surfaces them in the palette, context pad, and replace menu simultaneously.

2. Element Templates

Rather than requiring users to manually input raw XML properties, the modeler supports Camunda-compatible Element Templates via @bpmn-io/element-template-chooser.

Element Templates transform the right-hand properties panel into structured form inputs tailored to your application's specific domain activities.

Example Template: send-notification.json

{
  "$schema": "https://unpkg.com/@bpmn-io/element-templates@0.8.0/resources/element-template.json",
  "name": "Send Notification Activity",
  "id": "saccharine.activity.send-notification",
  "appliesTo": ["bpmn:ServiceTask"],
  "properties": [
    {
      "label": "Delivery Channel",
      "type": "Dropdown",
      "value": "mail",
      "choices": [
        {"name": "Email Mailable", "value": "mail"},
        {"name": "Slack Webhook", "value": "slack"},
        {"name": "System Audit Log", "value": "log"}
      ],
      "binding": {
        "type": "camunda:property",
        "name": "channel"
      }
    },
    {
      "label": "Recipient Template",
      "type": "String",
      "value": "{{ customer_email }}",
      "binding": {
        "type": "camunda:inputParameter",
        "name": "recipient"
      }
    }
  ]
}

When saved, these values are written to the BPMN 2.0 XML and compiled into the input_parameters JSON column on the workflow_nodes database table.

3. Real-Time Telemetry & Token Cockpit

The package includes an interactive execution viewer built with bpmn-js/lib/NavigatedViewer and paired with real-time polling endpoints (/tokens and /telemetry).

Dynamic Token Styling

Nodes on the canvas reflect live database execution states:

  • Completed Nodes (.bpmn-history-completed): Displayed with solid blue outlines and backgrounds, indicating that the token passed through the node successfully.
  • Active Waiting Nodes (.bpmn-active-token): Highlighted with an emerald green border and a pulsing CSS indicator, showing that a coroutine is currently hibernated at this step.
  • Failed / Halted Nodes (.bpmn-failed-token): Rendered in red, showing where an unhandled exception occurred or where an administrative halt stopped the process.

Interactive In-Page Signals

Clicking an active User Task node on the canvas opens a modal displaying current $userData and available action buttons (such as Approve, Reject, or Request Changes). Submitting the modal immediately sends the required inbox signal to resume background queue processing.

4. Filament v5 Admin Integration (Stub-Based)

The package provides the php artisan bpmn:filament command, which copies ready-to-use Filament resource stubs into your application. You then register those resources in your existing Filament panel provider.

Scaffolding Filament Resources

Run the following Artisan command to publish resource stubs into your app:

php artisan bpmn:filament --demo

This publishes:

  • app/Filament/Resources/Bpmn/WorkflowDefinitionResource.php — Manage workflow keys, versions, and deployment states.
  • app/Filament/Resources/Bpmn/WorkflowInstanceResource.php — Inspect active, completed, suspended, and failed workflows.
  • app/Filament/Resources/Bpmn/DemoOrderResource.php (with --demo) — Interactive CRUD for testing model event triggers.

Each resource includes its own page classes (e.g., ListWorkflowDefinitions) copied from the package stubs at resources/stubs/filament/. Use --force to overwrite existing stubs.

Registering in Your Filament Panel

After scaffolding, add the resources to your panel provider (app/Providers/Filament/AdminPanelProvider.php):

use App\Filament\Resources\Bpmn\WorkflowDefinitionResource;
use App\Filament\Resources\Bpmn\WorkflowInstanceResource;

public function panel(Panel $panel): Panel
{
    return $panel
        ->default()
        ->id('admin')
        ->path('admin')
        ->resources([
            WorkflowDefinitionResource::class,
            WorkflowInstanceResource::class,
        ]);
}

Included Resources

  • WorkflowDefinitionResource: Manage workflow keys, versions, and deployment states. Includes a fullscreen modal canvas for updating and compiling diagrams.
  • WorkflowInstanceResource: Inspect active, completed, suspended, and failed workflows. Includes header actions to Suspend, Resume, or Halt running instances.
  • Authorization: All package resources enforce standard Laravel policies defined in Saccharine\Bpmn\Policies\. Permission values include Bpmn:View, Bpmn:Edit, Bpmn:Delete, Bpmn:SuspendInstance, Bpmn:ResumeInstance, and Bpmn:HaltInstance.

The standalone Blade dashboard at the default address/bpmn/workflows/definitions remains available even without Filament. Filament integration is entirely optional and stub-based — no package-level render hooks or global asset injection are performed. The UI filtering for the modeler (Palette, Context Pad, Replace Menu) is dynamically driven by `engineCapabilities.js` to ensure only supported BPMN elements are available.
